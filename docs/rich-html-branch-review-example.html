This PR sorts into four change-types — clusters named by what each group of changes is for, not by which folder it touches. branch-review-command is the headline: the single new file that defines the command's behaviour. The other three exist only to land it — promote-to-third-command registers it across the plugin's shared contract and public manifests; docs-propagation threads it through every human-facing page; spec-002-record closes the repo's spec-workflow loop.

The split is deliberate: the one cluster carrying real behaviour is isolated from the mechanical support work, so you spend attention where the risk is and skim the rest. Because each name states an intent, “which part actually matters?” is answerable from the cluster list alone — the headline is the untagged one.
