The Claude Code plugins I use every day, published as one marketplace.

A personal, installable marketplace of custom skills, agents, and slash commands — from sketching an idea as a faithful clickable mockup, to framing it into specs and shipping each as an evidence-backed PR, to proving the feature runs against the real app. Install what you want; each plugin stands on its own.

Install

Add the marketplace, install a plugin, reload

This repo is the marketplace (moacyr-skills). Register it once, then install any plugin — spec-workflow pulls its live-verify dependency in automatically.

claude code
# 1 · register the marketplace (once)
/plugin marketplace add moacyrricardo/skills

# 2 · install what you want
/plugin install spec-workflow@moacyr-skills   # pulls live-verify with it
/plugin install rich-html@moacyr-skills       # report + decide
/plugin install prototype@moacyr-skills       # clickable mockups
/plugin install utils@moacyr-skills           # standalone helpers

# 3 · activate in the current session
/reload-plugins

Commands are namespaced by their plugin — /spec-workflow:new, /rich-html:report, /prototype:mockup. Prefer to try before installing? Clone the repo and pass --plugin-dir ./plugins/<name>. Full details in the README.

What's in the box

Five plugins, one marketplace

Each is independently installable with no hard cross-dependency (except spec-workflow → live-verify). Cards with a guide link through to a full walkthrough.

spec-workflow
depends on · live-verify

Spec-driven development: a numbered specs/ catalog and the commands + autopilot agent that drive a decision from todo → doing → an open PR, with issue-tracker and live-app verification wired in.

Read the guide
rich-html
standalone

Turn your work into self-contained interactive HTML. report synthesizes heterogeneous sources into a readable document; decide aggregates pending decisions into a surface that emits one prompt to execute them.

Read the guide
prototype
standalone

Turn a half-formed UI idea into a faithful, clickable HTML mock in the product's own look — often the first move: verify an idea before writing a spec, or lay out concern options to compare. mockup clones the real status-quo page and applies only your change, declaring its fidelity basis in a toggleable overlay.

Read the guide
live-verify
standalone · installed with spec-workflow

Prove a feature works against a running app: start the dev server, then drive it (a real browser or curl) to capture a screenshot / GIF / text verdict. Reusable primitives with no spec or tracker coupling.

Covered in the spec-workflow guide
utils
standalone

A catch-all for small standalone helpers. Currently stacked-merge — squash-merge a PR or a chain of stacked PRs into main, handling the rebase bookkeeping between each.

See the README reference
